# Gina 回覆文字格式規範

這份文件記錄 Gina 對話介面目前使用的回覆文字格式，供設計、內容與前端開發共同參考。適用範圍包含 AI 回覆、使用者訊息、表格、清單、引用、互動選項、執行步驟與長篇內容。

實際樣式以 [`tokens.css`](./dist/tokens.css) 與 [`app.css`](../app.css) 為準。

## 1. 設計原則

- 維持 Giant 內部 AI 工具的專業、清楚與安定感。
- 回覆內文使用 Regular，不以粗體反覆強調內容。
- 只有標題可以使用 Semibold；表格欄位名稱可使用 Medium。
- 回覆文字不另外增加字距，統一使用 `letter-spacing: normal`。
- 中文內容以較寬鬆的行高提升長文閱讀性；資訊密度較高的表格與介面標籤使用標準行高。
- Emoji 只能搭配標題使用，放在標題最前方，每個標題最多一個。
- 不使用文字顏色區分語意。層級以字重、間距、邊框與背景呈現。

## 2. 基礎字型設定

| 項目 | 設定 | 使用說明 |
| --- | --- | --- |
| 主要字型 | `Inter, "Noto Sans TC", -apple-system, BlinkMacSystemFont, "PingFang TC", "Segoe UI", sans-serif` | 一般回覆、標題、表格、標籤與按鈕 |
| 等寬字型 | `ui-monospace, SFMono-Regular, Menlo, monospace` | 程式碼、技術內容與長篇原始文字 |
| Regular | `400` | 所有一般內文 |
| Medium | `500` | 表格欄位名稱與少數介面標籤 |
| Semibold | `600` | 回覆標題、卡片標題 |
| Bold | `700` | 回覆內容目前不使用 |
| 預設字距 | `normal` | 所有回覆格式，不額外壓縮或拉開字距 |

## 3. 回覆文字層級

| 文字角色 | 字型 | 字級 | 字重 | 行高 | 字距 | 使用時機 |
| --- | --- | ---: | ---: | ---: | --- | --- |
| AI 回覆內文 | Sans | `15px` | `400` | `1.8` | `normal` | 說明、摘要、回答與一般段落 |
| 使用者訊息 | Sans | `15px` | `400` | `1.8` | `normal` | 使用者送出的文字 |
| 回覆區段標題 | Sans | `15px` | `600` | `1.8` | `normal` | 將較長回覆分成可掃讀的段落 |
| 操作卡片標題 | Sans | `16px` | `600` | `1.5` | `normal` | 需要使用者確認的動作或摘要 |
| 表格內文 | Sans | `14px` | `400` | `1.5` | `normal` | 欄位資料與比較內容 |
| 表格欄位名稱 | Sans | `14px` | `500` | `1.5` | `normal` | 表格第一列欄位名稱 |
| 互動選項 | Sans | `13px` | `400` | `1.5` | `normal` | Gina 需要補充資訊時，顯示在該則回覆下方的選項 |
| 狀態文字 | Sans | `13px` | `400` | `1.5` | `normal` | 執行中、讀取中或簡短系統狀態 |

## 4. 一般段落

一般回答、摘要與說明使用 `15px / 400 / 1.8`。連續段落之間保留 `12px`，讓中文長文容易追蹤行次。

**使用時機**

- 直接回答使用者問題。
- 補充背景、原因或限制。
- 一個主題可以在兩到四句內完整說明。

**內容規則**

- 內文中的 `<strong>` 與 `<b>` 會沿用一般字重，不顯示為粗體。
- 需要強調時，優先改寫句子順序，將重點放在句首。
- 不使用不同文字顏色標示關鍵字。
- 段落不需要手動加入額外空白行，元件會統一處理段落間距。

## 5. 標題與結構化內容

回覆區段標題使用 `15px / 600 / 1.8`，標題上方保留 `24px`，標題與說明之間保留 `6px`。較小的內容標題使用相同字級，上方 `16px`、下方 `8px`。

結構化文件的內容容器使用中性淺灰背景，讓欄位層級與一般段落有所區隔。

**使用時機**

- 回覆包含兩個以上不同主題。
- 需要讓使用者快速掃描步驟、比較結果或結論。
- 結構化文件需要顯示背景、目標、範圍、限制等欄位。

**標題寫法**

```md
### 📊 比較結果

### ✅ 建議做法

### 📌 注意事項
```

- 標題應簡短，建議控制在一行內。
- Emoji 必須與內容直接相關，不作為裝飾重複使用。
- 標題之外的內文維持 Regular。

## 6. 條列式清單

清單沿用回覆內文的 `15px / 400 / 1.8`。清單與前後內容保留 `8px`，左側縮排為 `22px`；編號清單的左側縮排為 `26px`，項目之間保留 `6–8px`。

**使用時機**

- 呈現三個以上平行重點。
- 說明有明確順序的操作步驟。
- 將複雜內容拆成可快速掃讀的短句。

**使用規則**

- 有先後關係時使用編號清單。
- 沒有先後關係時使用項目符號清單。
- 同一份清單的句型保持一致。
- 每個項目聚焦一個動作或觀點，避免在單一項目中放入多個長段落。

## 7. 表格

表格使用 `14px / 1.5`。欄位名稱使用 Medium `500`，資料內容使用 Regular `400`。儲存格垂直間距為 `12px`，欄位之間保留 `12px`。表格只用水平分隔線整理列，不使用大面積色塊或過多框線。

**使用時機**

- 比較相同欄位下的多個項目。
- 整理需求清單、狀態、負責人或優先級。
- 資訊需要以欄位對齊後才能快速判讀。

**使用規則**

- 欄位名稱保持簡短。
- 儲存格內容維持一般字重。
- 避免在表格內加入多層清單或其他卡片。
- 小螢幕可水平捲動，內容不強制壓縮到難以閱讀。

## 8. 問答格式

Q&A 內容沿用 `15px / 400 / 1.8`。每組問答使用獨立區塊，內距為 `12px`，問與答之間保留 `6px`，不同問答之間保留 `8px`。

**使用時機**

- FAQ 整理。
- 一次回覆多個明確問題。
- 需要讓問題與答案的關係比一般段落更清楚。

問題與答案都維持 Regular；`Q` 只作為結構標記，不使用粗體或額外色彩強調。

## 9. Block Quote

引用內容使用與內文相同的 `15px / 400 / 1.8`，不使用背景色，左側以 `2px` 淺灰直線區隔。區塊內距為 `8px 16px`。引用來源使用 `12px / 400 / 1.5`，與引用內容保留 `8px`。

**使用時機**

- 引用使用者先前提供的原文。
- 顯示郵件、文件或會議紀錄中的短段落。
- 將引用證據與 Gina 的解讀清楚分開。

```md
> 這是需要保留原意的引用內容。
>
> — 來源名稱
```

引用區塊不應用來呈現一般提醒、系統狀態或整段主要回答。

## 10. 互動式選項

互動選項顯示在提出澄清問題的 Gina 回覆下方，文字使用 `13px / 400 / 1.5`，按鈕最小高度為 `36px`。區塊標籤使用 `12px / 600 / 1.5`。

**使用時機**

- Gina 收到的資訊不足，需要使用者補充一項必要資訊。
- 使用者的選擇可以直接觸發下一步。
- 選項文字可以用短句清楚表達結果。

每次建議提供二到三個選項。選項應彼此互斥，並直接代表使用者的回答，例如會議長度可提供「30 分鐘」、「45 分鐘」與「60 分鐘」。資訊已足夠時不顯示此區塊。

## 11. 執行步驟、Skill、MCP 與 Agent Tag

回覆上方的執行資訊使用 `12px / 400 / 1.5`，顏色低於主要內容。收合狀態顯示步驟摘要與 Agent Tag；展開後以清單列出使用的 Skill、MCP 或工具。

**使用時機**

- 回覆實際呼叫 Agent、Skill、MCP 或外部工具時。
- 使用者需要理解回覆如何產生，或需要追蹤執行來源時。

**顯示規則**

- Agent Tag 顯示負責這次工作的 AI Agent 名稱。
- Skill 與 MCP 項目前方使用對應 Icon。
- 展開與收合只使用 Icon Button，並提供可存取的文字標籤。
- 沒有使用工具時，不顯示空的執行步驟區塊。

## 12. 長篇內容與程式碼

長篇內容使用等寬字型 `12px / 400 / 1.75`，文字不分色。預設顯示在高度 `240px` 的 Review Card 內，卡片內距為 `16px`，超出高度後可垂直捲動。

Review Card 使用與結構化文件一致的中性淺灰背景，不使用彩色底或語法分色。

**使用時機**

- 程式碼、設定檔、Log 或大量原始文字。
- 內容需要保留換行與空白格式。
- 全文會明顯拉長對話，影響前後訊息閱讀時。

**互動規則**

- Hover 卡片時，右上角顯示展開按鈕。
- 展開後由右側開啟 Review Panel，並將對話內容往中間收窄。
- Panel 右上角提供展開、複製與關閉操作。
- 卡片與 Panel 內只呈現純文字，不再嵌套其他小卡片。
- 程式碼目前不使用語法分色，所有文字維持同一顏色。

## 13. 回覆時間與操作

回覆時間使用 `12px / 400 / 1.5`。Copy 與 Download 為 Icon Button，排列在時間旁邊；圖示尺寸為 `14px`。

- Copy 複製目前回覆內容。
- Download 開啟格式選單，選項文字使用 `14px / 400 / 1.5`。
- 可下載格式包含 `.txt`、`.md`、`.png`、`.pdf` 與 `.docx`。
- Icon Button 必須提供 tooltip 或 `aria-label`，不能只依賴圖示讓使用者猜測功能。

## 14. 操作確認卡片

需要使用者確認的動作使用卡片呈現。卡片內文為 `15px / 400 / 1.8`，標題為 `16px / 600 / 1.5`，欄位名稱為 `14px / 600 / 1.5`，補充說明為 `14px / 400 / 1.5`。

**使用時機**

- 寄送郵件、建立事件或其他需要確認後才執行的動作。
- 需要讓使用者在執行前檢查收件人、內容、日期或影響範圍。

## 15. 文字與標點規則

- 中文內容使用全形標點符號。
- 中文與英文、數字之間保留一個半形空格，例如「使用 Outlook 查詢 3 封郵件」。
- 按鈕使用動詞或明確結果，例如「複製內容」、「整理成表格」。
- 標題不加句號；完整句子的內文使用句號。
- 避免連續驚嘆號、全大寫英文或過度口語的語氣。
- 專有名詞使用產品正式名稱，例如 `Outlook`、`MCP`、`Skill`、`Agent`。
